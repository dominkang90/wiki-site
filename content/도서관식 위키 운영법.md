# 도서관식 위키 운영법

유튜버 신영선(AI탐구)이 [[LLM 위키 패턴]]을 2~3달 실제 운영하며 다듬은 방식.
위키를 **"도서관"**, AI를 **"사서"**에 비유한다 — 확정된 지식(책)만 꽂고,
사서가 분류·정리·청소를 맡는다.

## 핵심: 도서관 4대 규칙

1. **확정본만 꽂는다** — 초안·작업물은 작업 폴더에, 도서관엔 "완성된 책"만.
2. **한 자료 = 한 자리** — 같은 문서를 여러 곳에 두지 않는다 (중복은 사서가 잡음).
3. **고민되면 인박스** — 어디 꽂을지 모르겠으면 인박스에 툭. 분류는 사서 몫.
4. **삭제 금지** — 낡은 건 서고(legacy)로 옮긴다. 역사도 지식이다.

## 그가 운영하는 자동화 (참고용)

- **야간 사서** (매일 새벽 3:30): AI가 인박스에 쌓인 자료를 알아서 분류·정리
- **위생 검사** (매일 새벽 3:15): 낡은 자료·모순 검사 후 리포트 발행, 개선 제안
- **주간 리포트** (월요일): 위키 상태 요약
- log.md에 **어떤 AI가 접근했는지도** 기록 → 여러 AI가 함께 써도 추적 가능

## 그의 도서관 분류 (사업용 예시)

경영본부 / 사업포트폴리오 / 조직운영 / 제품서비스 / 고객시장 / 콘텐츠마케팅 /
데이터재무 / 지식자산 / 회의결정 + 인박스 / 인덱스 / 대시보드 / 서고(legacy)

## 활용 아이디어: 업무 매뉴얼(SOP) 자동 기록

화면 녹화 확장 프로그램으로 실제 업무 과정(클릭·화면 캡처)을 자동 기록 →
마크다운+이미지로 저장 → 위키에 넣기. 반복 업무의 **인수인계 매뉴얼**이 쌓인다.
다음에 같은 일을 할 때 AI가 과거 매뉴얼을 근거로 답하거나 대신 수행.

## 그가 말하는 주의점

- 쓸수록 위키가 **비대해지고 무거워진다** — 지속 가능한 유지보수 시스템이 관건.
- 정답은 없다. 각자 목적에 맞게 규칙을 계속 다듬어야 한다 (스키마 공진화).
