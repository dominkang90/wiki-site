# LLM 위키 패턴

이 위키 시스템의 바탕이 된 방법론. **LLM(Claude 같은 AI)이 사람 대신 지식 위키를
쓰고 관리한다**는 아이디어다.

## 핵심 아이디어

- 보통의 방식(RAG, NotebookLM 등)은 질문할 때마다 문서 더미에서 조각을 찾아
  매번 처음부터 답을 조립한다. **쌓이는 게 없다.**
- 이 패턴은 다르다: 자료가 들어올 때마다 LLM이 읽고, 핵심을 뽑아,
  **서로 연결된 위키 페이지로 미리 정리해 둔다.** 지식이 한 번 정리되면
  계속 최신으로 유지되고, 자료가 늘수록 위키가 점점 똑똑해진다.
- 역할 분담: **사람 = 자료 고르기 + 질문하기**, **LLM = 요약·연결·목차·일지 등
  귀찮은 관리 전부**. 사람이 위키를 직접 쓰는 일은 거의 없다.
- 비유: "Obsidian은 편집기, LLM은 프로그래머, 위키는 코드베이스."

## 3층 구조

1. **raw (원본)** — 절대 수정하지 않는 원본 자료함. 진실의 근원.
2. **wiki (위키)** — LLM이 전부 쓰고 관리하는 페이지들.
3. **schema (규칙서)** — LLM이 지킬 규칙을 적은 문서(CLAUDE.md).
   이게 있어야 LLM이 "그냥 챗봇"이 아니라 "규율 있는 사서"가 된다.

## 3가지 작업

| 작업 | 내용 |
|---|---|
| 넣기(Ingest) | 자료 하나가 들어오면 요약 페이지 작성 + 관련 페이지 10~15개 갱신 + 목차·일지 갱신 |
| 묻기(Query) | 목차에서 관련 페이지를 찾아 근거와 함께 답변. 좋은 답은 다시 위키에 저장 |
| 점검(Lint) | 모순·고아 페이지·빠진 개념·낡은 주장을 주기적으로 청소 |

## 왜 통하나

위키가 망하는 이유는 읽기나 생각이 아니라 **관리(북키핑)가 귀찮아서**다.
LLM은 지루해하지 않고, 링크 갱신을 까먹지 않고, 한 번에 15개 파일을 고칠 수 있다.
관리 비용이 0에 가까워지니 위키가 계속 살아있다.
1945년 Vannevar Bush의 Memex(개인 지식 저장소 구상)와 같은 정신 — Bush가 못 풀었던
"누가 관리하나" 문제를 LLM이 푼다.

## 이 위키에 적용된 것

- 구조·규칙은 `CLAUDE.md`에 그대로 구현됨 (raw/wiki/index/log)
- 검색엔진(qmd), Marp 슬라이드, Dataview는 아직 안 씀 — 필요해지면 추가
- 실제 운영 사례와 추가 규칙은 [[도서관식 위키 운영법]] 참고
